01Deployment

One Docker Compose host runs three app containers, plus four optional monitoring ones. Only nginx is published: Postgres and the backend have no host ports at all. The backend is the only container that talks to the database, the proof-file volume and the outside mail server.

  • nginx proxies /api/ and /uploads/ to backend:5000, caches static assets for a year and falls back to index.html for client routes.
  • Proof files live on the bind mount, not in Postgres. scripts/backup.sh archives the database dump and the uploads together.
  • Only the frontend is published, on HTTP_BIND (default 80). Compose refuses to start while a required setting is blank. The full list is in ENV_SETUP.md.
  • Compose sets TZ=Asia/Kolkata, so the 09:00 jobs run at 09:00 IST. Both images run Node 24.

02Request path through the API

Every request passes the same middleware in the same order, set in app.ts. The last three stages decide whether the caller may do what they asked. Authorization is layered: a role check on the route, then an ownership and same-department check inside the controller.

  • authenticate verifies the access JWT (HS algorithm pinned), loads the user's active roles, and rejects any token whose tokenVersion no longer matches the user row.
  • reviewerGuard is added on POST /appraisals/:id/review only. It keeps a reviewer inside their department and stops faculty reviewing their own appraisal.
  • Proof files are never served statically. GET /api/uploads/file/:name checks who is asking and rejects path traversal.
  • gaptrust proxy is hard-coded to 1 (app.ts:72), but production sits behind two proxies (campus and nginx). Until the deployment team changes it to 2, every user shares one IP for the rate limits.

03Backend modules

The backend has four layers, and calls only go downward. Controllers own HTTP and permission checks. Services own the rules, and are pure where they can be: the scoring, tracking and cadre engines do no I/O. Only Prisma touches the database.

04Appraisal lifecycle

Each faculty member files one appraisal per academic year, and it moves through eight statuses. The orange path is the normal route. A rejected proof parks the appraisal on HOLD until the faculty replaces the proof, the HoD clears the hold, or the 14-day deadline voids those marks.

05Scoring: one engine, many readers

Every score, whether a form badge, a PDF column, a review-page card, a tracking figure or an email remark, comes from scoringEngine.ts. The frontend keeps a pure copy for live badges, and a shared fixture proves the two agree. The HoD's Cat 6 marks are added only at review, then frozen.

  • Four files move together: the engine, its frontend port, scoring-fixture.json and scoring-expected.json. Parity suites on both sides fail if one moves alone.
  • The review row stores the self total next to the reviewed total. A later rule change then cannot move one figure without the other.
  • The HoD may override any Cat 1–5 mark. Each category is clamped to its maximum, and both assessments reach HR separately.
  • Tracking measures against the /550 grand total for the principal and the faculty's own HoD; the dean and special scrutinizers, who may not see Category 6, read the same rows at the reviewed /500. Eligibility is decided on the full total either way, so the verdict does not move with the viewer.

06Email: an outbox, not a send

Nothing in a request sends mail. Code writes a row to an outbox table, and a worker inside the backend process sends it within 30 seconds. So a slow or failing mail server never slows a user's click, and every mail leaves a record.

  • A dedupe key names one event: the proof URL, the hold's time, the submission time, the review time or a hash of the issued text. A double-click mails once, and a genuine repeat mails again.
  • Status mail (approvals, holds, OTPs) ignores the opt-out. Only reminders, digests and the quarterly email honour it.
  • Templates escape every faculty-typed value. The quarterly payload carries no cadre, tier, eligibility or /550 figure.
  • Once a mail is sent, or finally fails, the password-OTP code is redacted from the stored payload.

07Sign-in and tokens

A login returns a short-lived access token in the response body and a refresh token in a cookie the page's scripts cannot read. Every protected call re-checks a per-user version number. Logging out, or resetting or changing a password, bumps that number and kills every token already issued.

  • Forgot password sends a 6-digit OTP from crypto.randomInt, limited to 3 requests a minute. It returns the same message whether or not the code exists.
  • Soft-deleted users cannot sign in. Reactivation restores the account but not its roles, which are re-assigned on purpose.
  • A HoD or reviewer role carries a department and is valid only in the user's own department. The principal, the dean and the scrutinizer pool are the cross-department roles; a scrutinizer reaches one submission at a time, through its FinalReview assignment.
  • Default passwords (Welcome@123 for imports) come from environment variables. The real install still has to set them and force a reset.

08Data model

The schema has 54 Prisma models. At its centre is AppraisalSubmission: one per faculty member per academic year, carrying 32 category tables that mirror the official form, section by section. Reviews, proof checks and feedback hang off the submission. Tracking settings hang off the year.

09Frontend

The frontend is one React single-page app. The routes a user can open depend on their roles, but that is navigation only. The server re-checks every request (section 02), so hiding a page never grants or denies anything by itself.

  • Routing: React Router 7. ProtectedRoute sends signed-out users to /login and hides pages outside the user's roles.
  • Session: a zustand store persists the access token. One axios instance calls relative /api with credentials, and on a 401 it refreshes once and retries.
  • The form: react-hook-form + zod, in 7 steps: Leave & Info, Cat 1 to Cat 5, then Preview & Submit. Live badges and the working under each row come from utils/scoring.ts.
  • Views: recharts for dashboards, SheetJS for Excel export. Tailwind 4 tokens set the institutional palette: navy #1e3a5f, saffron #e9a93a, EB Garamond headings over Lato.
